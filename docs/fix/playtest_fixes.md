## 📋 작업 방식 — 2-문서 워크플로우

```
세션 진입 시 읽을 문서 (고정 2개):
  ① docs/fix/playtest_fixes.md  (이 문서)          — 포커스 확인 + 룰 + 템플릿
  ② docs/fix/focus_<NN>_<name>.md  (현재 포커스)  — 원본 근거 / 작업 / 체크리스트

작업 순서:
  1. ① 읽고 "현재 포커스" 번호 확인
  2. ② (해당 포커스 파일) 열어 "진행 상황" + "원자 단위 작업 목록" 확인
  3. 다음 미완료 원자 작업 진행 → 완료 전 검증 체크리스트 통과 → [x]
  4. 컴파일 → 커밋 → ② 의 "작업 기록" 에 세션 로그 추가
  5. 모든 원자 작업 [x] + 회귀 방지 검증 통과 시 → ① 의 "현재 포커스" 갱신

절대 규칙:
  - 다른 포커스는 현재 포커스 완료 전까지 손대지 않는다
  - 원본 근거(리서치 파일 코드)가 없으면 그 자리에서 Agent WebFetch 로 보완
  - 수정 중 발견한 신규 이슈는 ② 의 "신규 발견" 에 기록하고 현재 작업 계속
```

## 1:1 번역 룰 (PORTING_RULES.md + checklist_original_audit.md 통합)

```
원칙 1. 원자 단위 원칙
   항목 하나 = 원본 동작 하나. "X 기능 구현" 같은 복수 동작 금지.

원칙 2. 완전 추출 원칙
   리서치 단계에서 원본 클래스의 모든 메서드 × 모든 분기 × 모든 상수를
   빠짐없이 추출. 기록되지 않은 동작은 구현 대상이 아니다.

원칙 3. 추적 가능성 원칙
   코드에 TODO / [미확인] / 빈 메서드가 존재하면 반드시 대응 항목이
   해당 포커스 파일 또는 PENDING_RESEARCH.md 에 등록되어 있어야 한다.

원칙 4. 미확인 차단 원칙 (감사 규칙 B)
   설계 근거(리서치 파일의 원본 코드)가 없으면 구현하지 않는다.
   "아마 이럴 것이다"로 코드를 작성하지 않는다.
   리서치 파일에 없는 동작은 → 리서치 파일을 먼저 보완한다.

원칙 5. 완료는 검증 이후 원칙
   항목을 [x]로 바꾸기 전에 완료 전 검증 체크리스트를 통과해야 한다.

감사 규칙 A. 전체 읽기 원칙
   리서치 파일은 처음부터 끝까지 전부 읽는다.
   대응 구현 파일도 처음부터 끝까지 전부 읽는다.

감사 규칙 C. 즉시 수정 원칙
   불일치를 발견한 순간 그 자리에서 수정한다.

감사 규칙 D. 불일치 3분류
   [오역]   구현이 원본과 다른 값/조건/로직을 사용한다
   [누락]   원본의 분기·상수·조건이 구현에 존재하지 않는다
   [잉여]   원본에 없는 로직이 구현에 추가되어 있다
```

**우선순위**: 이 문서 > PORTING_RULES.md > CLAUDE.md > 개인 판단.

## 공통 완료 전 검증 체크리스트 (각 원자 작업 단위)

```
[근거]   의존 리서치 문서에서 관련 메서드/분기를 다시 읽었다
[근거]   리서치 파일에 해당 원본 코드가 있다 (없으면 WebFetch 보완 후)
[대응]   원본 코드와 구현 코드가 side-by-side 로 1:1 대응된다
[분기]   리서치 문서에 기록된 모든 분기(if/else)가 코드에 존재한다
[상수]   리서치 문서에 기록된 모든 상수가 코드에 반영되었다
[타이밍] 메서드 호출 타이밍(훅 위치)이 원본과 일치한다
[근사]   근사 이식이면 "근사 이식 — 원본과 차이: X" 주석이 달려 있다
[신규]   구현 중 발견한 신규 누락은 ② 의 "신규 발견" 에 등록했다
[회귀]   이 수정이 다른 완료된 이식을 깨뜨리지 않는다 (공통 회귀 감사 참조)
[빌드]   `./gradlew build` 성공
```

```
    grep "// TODO\|// \[미확인\]\|// 아마\|// 추정" <수정 파일>

[B] 이번 수정이 바꾼 public 필드/메서드 시그니처를 사용하는 다른 호출처를
    전부 찾아 여전히 정상 동작하는지 컴파일 경고/에러 확인

[C] 공통 플래그(enabled / isCrawling / isSlow / isFast / toggler / sneakToggled 등)
    의미가 변경됐다면 checklist_original_audit.md 에서 해당 플래그를 쓰는 이전
    완료 항목들을 재검토 (grep 로 필드명 검색)

[D] 네트워크 페이로드(ConfigContentPayload / StatePayload / SpeedChangePayload 등)
    포맷이 바뀌었다면 서버/클라 양측 송수신이 모두 수정됐는지 확인
```

## 공통 원본 소스 WebFetch 프롬프트 템플릿

리서치 파일에 원본 코드가 부족할 때 Agent 에 던질 프롬프트 기본 형태:

```
SmartMoving 1.7.10 원본에서 다음 정보를 덤프해 주세요. 해석·요약 금지,
원본 Java 코드 그대로.

대상 URL:
  - https://raw.githubusercontent.com/makamys/SmartMoving/master/src/main/java/net/smart/moving/<경로>.java
  - (필요 시 추가)

추출 대상:
  1. <필드명> / <메서드명> — 선언 + 사용처 전체
  2. <특정 블록 L<시작>-L<끝>> — 주변 맥락 포함 덤프
  3. <원본 API 이름>  — 1.21.1 Yarn 매핑 힌트와 함께

응답 형식:
  - 각 블록 앞 `// --- <파일명> L<start>-L<end> ---` 표기
  - 원본 그대로 (줄번호, 들여쓰기, 주석 포함)

이 정보는 1.21.1 Fabric 포트의 1:1 이식에 사용됩니다.
```

## 공통 포커스 파일 구조 명세

모든 `focus_NN_*.md` 파일은 아래 섹션 순서를 **고정**으로 따른다:

```
1.  진행 상황              — 상태 / 현재 단계
2.  증상                   — 원본 vs 현재 차이 요약
3.  재현 케이스 표         — 구체적 입력 / 기대 / 실제
4.  의존 관계              — 선행 포커스 / 영향받는 포커스
5.  원본 근거              — 리서치 경로 + 원본 Java 코드 임베드
                             (부족 시 WebFetch 프롬프트 준비)
6.  1:1 매핑 테이블        — 원본 심볼 ↔ 1.21.1 심볼
7.  구조적 차이 / 근사     — 재현 불가 지점 명시
8.  현재 구현 스냅샷       — 수정 전 코드 (변경 단위별)
9.  예상 수정 diff         — 수정 후 예상 형태
10. 원자 단위 작업 목록    — [ ] 체크박스
11. 호출 타이밍 검증       — 원본 호출자 / 1.21.1 호출자 일치 확인
12. 테스트 프로토콜        — 인게임 검증 방법 / 측정 값
13. 완료 전 검증 체크리스트 — 포커스 고유 항목 + 공통 체크
14. 회귀 방지 감사         — 공통 감사 적용 결과
15. 작업 기록              — 세션별 시간순 로그
16. 신규 발견              — 구현 중 발견한 누락/오역
17. 잔여 / 후속            — 이 포커스 범위 초과 — 새 포커스 후보
```

### 2.3 의미 식 (원자단위)

```
sa.moveFlying(strafe, forward, friction):
  f4 = strafe² + forward²
  if f4 < 1.0E-4F: return
  f4 = sqrt(f4)
  if f4 < 1.0F: f4 = 1.0F                  // 정규화는 magnitude > 1 일 때만
  f4 = friction / f4                       // 유효 보폭 인자
  strafe *= f4
  forward *= f4
  f5 = sin(yaw * π/180)
  f6 = cos(yaw * π/180)
  motionX += strafe * cos - forward * sin
  motionZ += forward * cos + strafe * sin
```

> **포인트**: `if f4 < 1.0: f4 = 1.0` 은 input vector 의 magnitude 가 1 이하일 때 정규화하지 **않음**. 즉 (forward=1, strafe=0) 같은 단축 입력은 그대로 friction 만큼 가속, 대각선 (forward=1, strafe=1, magnitude=sqrt(2)≈1.414) 은 friction/1.414 곱으로 단위벡터화.
> Y motion 은 건드리지 않음.

## 13. 검증된 식 — 예시 시나리오

### 13.1 평지 (slipperiness 0.6), 일반 walking, W 단방향
- onGround = true, isSprinting = false, no SPEED
- attribute.computed = 0.1
- f3 = 0.6 × 0.91 = 0.546
- f4 = 0.16277136 / 0.546³ = 0.16277136 / 0.16276568 ≈ **1.000003**
- friction = 0.1 × 1.000003 = 0.1
- moveFlying(0, 1, 0.1):
  - magnitude = 1, max = 1, f4_mf = 0.1 / 1 = 0.1
  - strafe' = 0, forward' = 0.1
  - motionX += 0 - 0.1 × sin(yaw)
  - motionZ += 0.1 × cos(yaw)
- post-damping:
  - motionX *= 0.546
  - motionZ *= 0.546
- terminal velocity (geometric series with ratio 0.546 + 첫 가속 0.1 매 tick):
  - v_terminal_per_tick (cos-방향) = 0.1 / (1 - 0.546) ≈ **0.220 m/tick**
  - 초당 (20tick) ≈ 4.40 m/s

### 13.2 평지, sprint = true, no SPEED
- attribute.computed = 0.1 × (1 + 0.3) = **0.13**
- f4 ≈ 1.000003 (동일)
- friction = 0.13 × 1.000003 = 0.13
- moveFlying(0, 1, 0.13): forward' = 0.13
- terminal motion = 0.13 / (1 - 0.546) ≈ **0.286 m/tick** ≈ 5.72 m/s

### 13.3 평지, sprint, SPEED LV2 (amp=1)
- SPEED amount per level = 0.2 × 2 = 0.4
- attribute.computed = 0.1 × (1 + 0.4) × (1 + 0.3) = 0.1 × 1.4 × 1.3 = **0.182**
- friction = 0.182 × 1.000003 ≈ 0.182
- terminal motion = 0.182 / (1 - 0.546) ≈ **0.401 m/tick** ≈ 8.02 m/s

### 13.4 ICE 위 sprint, no SPEED
- block.K = 0.98
- f3 = 0.98 × 0.91 = 0.8918
- f4 = 0.16277136 / 0.8918³ = 0.16277136 / 0.70921... ≈ **0.22951**
- attribute.computed = 0.13 (sprint)
- friction = 0.13 × 0.22951 ≈ 0.02984
- moveFlying(0, 1, 0.02984): forward' = 0.02984
- terminal motion = 0.02984 / (1 - 0.8918) ≈ **0.276 m/tick**

> ICE 가 일반 평지 sprint (0.286) 보다 약간 느리지만, **가속이 매우 느림** (시작 0.03 vs 0.13). 그래서 짧은 거리 ICE 는 느리게 느껴짐. 장거리 미끄러짐은 0.8918 damping 때문에 멈추는데 오래 걸림.

### 13.5 SoulSand 위 sprint, no SPEED
- block.K = 0.6 (default)
- f3 = 0.546, f4 ≈ 1.000003
- attribute.computed = 0.13
- friction = 0.13
- moveFlying 후 motion += 0.13 in cos direction
- post-damping: motion *= 0.546
- 추가: ano.a(...) — entity collided 호출 매 tick: motion *= 0.4
- 결합 damping ratio: 0.546 × 0.4 = **0.2184**
- terminal motion = 0.13 / (1 - 0.2184) ≈ **0.166 m/tick**

### 13.6 공중 sprint (jumpMovementFactor)
- onGround = false, sprint
- aQ = 0.02 + 0.02 × 0.3 = **0.026**
- friction = 0.026 (직접 사용; 0.91 normalize 후는 거의 동일)
- moveFlying: forward' = 0.026
- 매 tick motion += 0.026 cos-방향, then *= 0.91
- terminal motion (공중에서 무한히 sprint 가정) = 0.026 / (1 - 0.91) ≈ **0.289 m/tick**

> 공중 sprint terminal ≈ 평지 sprint terminal (0.286). 1.7.10 에서 비행기 같은 높은 공중 sprint 를 유지하면 평지 동일 속도까지 가속.

## 14. 빠진 부분 / 추측 회피로 미수집

- **PotionEffect 의 매 tick 갱신** (sw.onUpdate 안 effect 적용 시점) — 본 문서의 sprint 직접 식과 무관 (이미 효과가 attribute modifier 로 등록되어 있으면 영향 즉시 반영). 정확한 effect tick 처리 흐름은 별도 분석 필요 시 검토.
- **Player.getJumpUpwardsMotion** (jump motion = 0.42 + sprint 시 forward boost 0.2 곱) — 본 분석은 walking sprint 만 다룸. jump 분석 별도.
- **Block.K 가 변경되지 않는 다른 vanilla 블록** — 전수 검색 결과 ICE/PACKED_ICE 만 확인됨. SOUL_SAND 는 K 변경이 아닌 onEntityCollidedWithBlock motion 곱 (확인됨). MAGMA_BLOCK 등은 1.7.10 에 없음 (1.10+ 추가).
- **Capability.f (flySpeed) 적용 위치** — sv.e(F,F) 비행 분기 (yw.b == true) 에서 다른 식. 본 분석에서 비행 walking 은 다루지 않음 (= 사용자 분석 목적은 평지 sprint).
- **abilities Modifier UUID** (Creative flySpeed/walkSpeed 가 attribute 에 추가 modifier 로 들어가는지) — 확인 결과 yz 안에 추가 UUID 정의 없음. 즉 1.7.10 vanilla 에서 Creative 의 추가 walking speed modifier 는 없음 (Creative = walkSpeed 그대로 0.1, 변경하려면 capabilities.walkSpeed 수동 변경).

## 15. 비교 — SmartMoving 매핑 시 확인 포인트

(사용자 reference 메모리 `feedback_air_sprint_rawspeed.md` 와 일치 확인)

- 1.7.10 에서 air sprint friction 식: `aQ + bJ × 0.3` = 0.02 + 0.006 = **0.026F**
- 이 값이 sa.moveFlying 의 `friction` 인자로 전달 → moveFlying 안에서 `friction / max(magnitude, 1)` → 단방향 입력 magnitude=1 → 그대로 0.026
- 1.21.1 vanilla 의 air friction 0.02 hardcoded 는 **sprint 영향 미반영 식**. 직접 매핑 시 0.026F 사용 (= 사용자 메모리 `feedback_air_sprint_rawspeed.md` 정정).

(reference 메모리 `reference_vanilla_movement_magic.md` 검증)

- 1.7.10 ground rawSpeed: `0.16277136 / (slip × 0.91)³`
- 1.21.1 vanilla ground (등가): 직접 식 다름 (yarn `LivingEntity.applyMovementInput` 에서 `Math.pow(0.91, 3)` 분리). 그러나 결과적으로 `0.21600002F / slip³ ≡ 0.16277/(slip × 0.91)³` (= 사용자 reference 메모리에서 검증됨).
- SPRINTING_SPEED_BOOST: 1.7.10 = sv.<clinit> 의 modifier (UUID `662A...`, 0.3, op=2). 1.21.1 yarn 의 SPRINTING_SPEED_BOOST attribute modifier 와 정확히 동일 (UUID 별칭 변경 없음 — 동일한 값 유지).

## 16. 결론

1.7.10 vanilla walking/sprinting 식은 다음 4개 핵심 메서드와 7개 핵심 상수로 구성:

핵심 메서드:
1. **sv.e(F,F)** [moveEntityWithHeading] — ground/air 분기, slipperiness 적용, motion damping
2. **sa.a(F,F,F)** [moveFlying] — input 정규화 + yaw 회전 + motion 누적
3. **sv.bl()** / **yz.bl() override** [getAIMoveSpeed] — attribute computed value 반환
4. **yz.e()** [onLivingUpdate] — 매 tick aQ 갱신 + setBaseValue + setAIMoveSpeed

핵심 상수:
1. **0.6F** — Block default slipperiness (aji.K)
2. **0.91F** — XZ damping multiplier
3. **0.16277136F** — ground rawSpeed coefficient
4. **0.02F** — base jumpMovementFactor (sv.aQ default + yz.bJ)
5. **0.3D** — sprint multiplier (yz.e() aQ 추가식 + sv 의 sprint modifier amount)
6. **0.1F** — walkSpeed default (yw.g + sv.bl() fallback + sv.aD() base)
7. **0.98F** — ICE/PACKED_ICE slipperiness

Sprint 동작 두 경로:
- **ground**: `sv.<clinit>` 의 sprint modifier (0.3, op=2) 가 movementSpeed attribute 에 설정/제거됨 → `bl()` 이 곱해진 computed value 반환 → `f4 * bl()` 로 friction 계산
- **air**: `yz.e()` 매 tick `aQ = 0.02 + 0.02 × 0.3 = 0.026F` 직접 set → moveFlying friction 인자
